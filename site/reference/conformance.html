What of the Avro 1.12 specification version 0.2.0 implements, and how that is checked.

In 0.2.0

Part of the specification Status
Schema declaration: primitive, complex and named types, aliases, defaults Complete
Logical types All of 1.12: decimal, big-decimal, uuid, date, time-millis, time-micros, timestamp-millis, timestamp-micros, timestamp-nanos, local-timestamp-millis, -micros, -nanos, duration
Binary encoding Complete; array and map blocks with a negative count and a byte size are read
Single-object encoding Complete
Schema resolution Complete
Parsing Canonical Form Complete
Fingerprints CRC-64-AVRO, MD5, SHA-256
Object container files Read and write, compression null and deflate

Not in 0.2.0

Part of the specification What happens instead
JSON encoding Not available
The compressions snappy, bzip2, xz, zstandardA file that uses one throws UnsupportedCompressionException when the reader is made
The IPC/RPC protocol and protocol declarations Not available; an error type is parsed and encoded as a record
Sort order A field's order is parsed and kept, but nothing compares by it

These may follow as minor versions. The package runs on the Dart VM and AOT, not on Flutter web.

Behaviour worth knowing

  • A union default is the value of the first branch it fits.
  • Named types match by their name without the namespace, or by the reader's aliases.
  • A logical type that the package does not know, or that is invalid, is read as its underlying type.
  • encode does not fill in defaults; every record field must be given.

The test oracles

dart test needs nothing but Dart. It checks the package against data that others wrote, so that it does not only agree with itself.

Oracle What it checks
Apache schema-tests.txt The canonical form and CRC-64-AVRO fingerprint of every schema in it
Apache interop.avsc Parsing and round trips of the Apache interop schema
Apache weather.avro, weather-deflate.avro, weather.jsonReading Apache's container files, compressed with null and deflate, to the records of weather.json
Apache syncInMeta.avro A file whose metadata contains its own sync marker
AXT examples Canonical forms, a single-object message of 210 bytes and a container file of 5,020 bytes, written by fastavro 1.13.1
Hand-written cases Byte-exact encodings worked out from the specification, for every type and logical type

The Apache files are copied unchanged from the Apache Avro repository, tag release-1.12.2, under the Apache License 2.0; weather-deflate.avro, which that tag lacks, comes from a later commit (AVRO-4172). The AXT examples come from AXT release v0.1.0, spec/envelope.md, section 10.

Interoperability with Python avro

A separate CI job round-trips data with the Python avro package 1.12.2, the official Apache library: Python writes and Dart reads, then Dart writes and Python reads. It covers four cases: the Apache interop schema, the logical types Python supports, a schema resolution with promotions, fields in another order, defaults and an enum default, and a union of primitives, two records and a map. Each case is compared as a container file with null, one with deflate, and as single datums: 12 comparisons in each direction, all passing.

Two gaps of Python avro 1.12.2 are left out of the job; the Dart tests cover both:

  • It writes a boolean in a union of boolean and double as a double.
  • It does not resolve an unknown enum symbol to the reader's default.

The job compares data, not fingerprints: Python avro 1.12.2 computes some canonical forms wrongly, such as {"type":"string"} for a primitive with a logical type. The fingerprints are pinned by schema-tests.txt.

What has no second implementation

Python avro does not support everything. These parts are checked by the hand-written cases from the specification only:

  • single-object encoding, which the AXT example message also checks, as written by fastavro;
  • timestamp-nanos;
  • local-timestamp-millis, -micros and -nanos;
  • big-decimal;
  • duration;
  • uuid on fixed.

Each is a thin layer over an encoding the interop job does check: long, bytes or fixed.

The big-decimal layout

A big-decimal carries its scale in each value. The package lays out the bytes of a value as the unscaled value first, as Avro bytes in big-endian two's complement, then the scale as an Avro int. This layout is believed to match the Java implementation, but it has not been checked against Java, and neither Python avro nor fastavro supports big-decimal.

Fuzzing

The two entry points that take untrusted bytes, AvroCodec.decode (with single-object encoding) and AvroFileReader with its records, are fuzzed by mutating valid inputs at random. A run fails on any input that throws anything but an AvroException, or takes longer than two seconds. dart test runs 2,000 mutations with a fixed seed; a weekly CI job fuzzes for ten minutes.
