The JSON that encodeJson writes and decodeJson reads, on AvroCodec and TypedCodec. The JSON encoding guide shows it at work.

The methods

Method What it does
encodeJson(value, {String? indent})The JSON text of value in the writer schema, compact, or indented by indent; a String
decodeJson(String json) The value of the JSON text of the writer schema, read as the reader schema, as decode returns it

Both go through the binary encoding of the writer schema, so every check of encode and decode applies, and so do resolution, logical types and decodeBranches. On TypedCodec, encodeJson takes and decodeJson returns the generated class.

Union branch names

Branch Written as Also read as
A named type Its full name: com.example.ClickIts simple name, Click, when no other branch of the union has that simple name
Any other type Its type name: int, string, array, mapNothing else
A logical type Its underlying type's name: long for timestamp-millisNothing else

These are the names of Branch and the names Apache Avro's Java implementation writes. The branch of a value is chosen as by encode; a value that fits more than one branch needs a Branch.

Errors and limits

Case Thrown
encodeJson: a value that does not fit the writer schemaEncodeException with the path of the value, as from encode
decodeJson: text that is not JSON DecodeException, offset 0, no path
decodeJson: JSON that is not a value of the writer schemaDecodeException, offset 0, the path in the JSON, such as $.payload
decodeJson: a union key that is not a branch, or the simple name of twoDecodeException, naming the branches
decodeJson: data that does not resolve to the reader schemaResolutionException, as from decode
decodeJson: JSON nested deeper than maxValueDepthLimitExceededException, before the text is parsed
Either: a value nested deeper than maxValueDepthLimitExceededException

A key repeated in a JSON object keeps its last value; the repetition is not detected.
