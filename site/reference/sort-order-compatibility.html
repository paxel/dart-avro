The APIs of the Avro sort order and of the compatibility check, as tables. The guides Sort order and Schema compatibility show them at work.

The comparison methods

Method Compares Throws
int AvroCodec.compare(Object? a, Object? b) Two values of the writer schema, as encode takes them EncodeException for a value that does not fit the schema; LimitExceededException beyond maxValueDepth; ArgumentError on a map
int AvroCodec.compareBytes(Uint8List a, Uint8List b)Two encodings of the writer schema, read side by side up to the first difference, without decoding themDecodeException for bytes that are not a valid encoding, as far as it reads; the limits as decode; ArgumentError on a map
int TypedCodec.compare(T a, T b) Two values of a generated class, by their generic values As AvroCodec.compare

Each returns -1, 0 or 1, and compare and compareBytes agree on the values and their encodings. A field with "order": "ignore" is not compared, so a map there throws nothing.

The order of each schema

Schema Order
null All equal
boolean false before true
int, longBy value
float By the 32-bit value it encodes to; -0.0 before 0.0; NaN after every other number and equal to itself
double By value; -0.0 before 0.0; NaN after every other number and equal to itself
bytes, fixedUnsigned bytes, lexicographically; a shorter prefix first
string Its UTF-8 bytes, unsigned, lexicographically
enum The index of the symbol
array Element by element, then by length
map None; ArgumentError
record Field by field in schema order: ascending (the default) as is, descending reversed, ignore skipped
union The index of the branch, then the value
decimal The bytes of its two's complement: a negative value after a positive one
duration Its 12 bytes, months, days and milliseconds each little-endian
other logical types As the underlying value they encode to: dates, times and timestamps in time order

The compatibility check

Member What it is
SchemaCompatibility checkCompatibility({required Schema reader, required Schema writer})Every reason data of writer cannot be read as reader by the resolution of AvroCodec, without data
bool SchemaCompatibility.isCompatible Whether every datum of the writer schema can be read as the reader schema
List<Incompatibility> SchemaCompatibility.incompatibilitiesEvery incompatibility, in the order of the schemas; unmodifiable; empty if compatible
IncompatibilityKind Incompatibility.kind The kind, below
String Incompatibility.message What is incompatible, in words
String Incompatibility.readerPath Where in the reader schema, such as Memo.tags[]; names only the reader's fields and branches
String Incompatibility.writerPath Where in the writer schema, as readerPath is in the reader's

The paths use the notation of ResolutionException: the schema's name, then .field, [] for array items, {} for map values and <branch> for a union branch. Incompatibility has value equality; its toString() reads Incompatibility(typeMismatch at Memo.tags[], writer Memo.tags[]: string does not resolve to long).

The kinds

IncompatibilityKind When Does AvroCodec(writer:, reader:) throw?
nameMismatch A named type of the writer has neither the reader's name nor one of its aliases Yes
fixedSizeMismatch The fixed sizes differ Yes
missingEnumSymbols The writer's enum has symbols the reader's lacks, and the reader's has no default No: decode throws ResolutionException for a datum with such a symbol
readerFieldMissingDefaultValue A reader field the writer lacks has no default Yes
typeMismatch The writer's type neither is the reader's nor promotes to it Yes
missingUnionBranch No branch of the reader's union takes the writer's type, or the writer's union has no branchYes
decimalMismatch The decimals differ in precision or scale; Java has no such kind Yes

The last column holds outside a writer's union. An incompatibility inside a branch of a writer's union, with <branch> in its writerPath, lets the codec be made as long as another branch resolves; decode then throws ResolutionException for a datum in that branch. Only when no branch resolves does the constructor throw.

The names follow SchemaIncompatibilityType of Apache Avro for Java where one matches.
