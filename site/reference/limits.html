The fields of AvroLimits, their defaults, and what happens over them. The Untrusted input and limits guide explains when to change them.

The fields

Field Default Bounds
maxSchemaBytes 1,048,576 (1 MiB) The JSON text of one schema, in UTF-8 bytes
maxSchemaDepth 64 The nesting of [ and { in a schema's JSON text, counted before it is decoded
maxValueDepth 1,024 The nesting depth of one value: each record field, array item, map value and union branch is one level
maxZeroSizeItems1,048,576 The item count of one array whose items take zero bytes, such as null; also the record count of a container block whose records take zero bytes
maxBlockBytes 67,108,864 (64 MiB) One block of a container file after decompression
maxTotalBytes 1,073,741,824 (1 GiB) All blocks of a container file together after decompression

Every field is an int?; null means no limit. const AvroLimits() has the defaults, and each named argument overrides one field. AvroLimits.none has every field null.

Who checks what, and what is thrown

Field Checked by Over the limit
maxSchemaBytes Schema.parse LimitExceededException
maxSchemaDepth Schema.parse LimitExceededException
maxValueDepth AvroCodec: decode, decodeSingleObjectLimitExceededException
maxValueDepth AvroCodec: encode, encodeSingleObjectLimitExceededException
maxZeroSizeItemsAvroCodec: decoding an array LimitExceededException
maxZeroSizeItemsAvroFileReader: the record count of a block LimitExceededException
maxBlockBytes AvroFileReader: records LimitExceededException, while iterating
maxTotalBytes AvroFileReader: records LimitExceededException, while iterating

LimitExceededException.limit is the name of the field, as in the first column. The limits of an AvroFileReader also parse the file's schema and make the codec of records(); a codec passed to records(codec) decodes with its own limits. AvroFileWriter parses a schemaJson you pass with the limits of its codec.

Always on

Whatever the limits, these throw DecodeException:

  • A declared length or count beyond the bytes that are left, checked before anything is allocated.
  • An array or map count that its items, at their smallest encoding, cannot fit into the bytes that are left.
  • A negative length, a varint longer than 64 bits, an int beyond 32 bits.
  • A string that is not well-formed UTF-8, encoded surrogates included.
  • A block that does not end with the sync marker, or whose records do not fill it exactly.
