Every failure caused by a schema, a value or the bytes you pass is an AvroException. The class is sealed, with one subtype per cause, so a switch over it is checked by the analyzer: when a cause is added, your code stops compiling instead of missing it.

The hierarchy

Exception Cause Carries
SchemaParseException The text is not JSON, or not a valid Avro schema path, or null
ResolutionException A writer schema does not resolve against a reader schemapath
DecodeException The bytes are not a valid encoding offset, path or null
EncodeException A value does not fit its schema path
LimitExceededException Input exceeds one of the AvroLimits limit
UnsupportedCompressionException A container file uses a compression other than null and deflatecompression

Each has a message that says what went wrong in words, and a toString() that adds where, such as EncodeException at $.age: expected int for int, got String. The exception reference lists, for each type, every place that throws it.

What the fields say

  • path of SchemaParseException: where in the schema, as the full name of the record and the index of the field, such as Memo.fields[1].type, or $ and an index from the root; null when the text is not JSON.
  • path of ResolutionException: from the codec's constructor, a place in the schemas, such as Memo.written; from decode, the place in the value, such as $.colour.
  • offset of DecodeException: the byte at which decoding failed, counted from the start of the bytes being decoded. For the records of a container file, it counts from the start of the decompressed block; for the block structure itself, from the start of the file.
  • path of DecodeException: the place in the value, when a logical type cannot be read, such as a timestamp-millis beyond the range of DateTime; null otherwise.
  • path of EncodeException: the place in the value: $ is the value, $.written.year a field of a field, $.items[2] an item of an array.
  • limit of LimitExceededException: the name of the AvroLimits field, such as maxBlockBytes.
  • compression of UnsupportedCompressionException: the value of the file's avro.codec, or the argument you passed to AvroFileWriter.

An exhaustive switch

Catch AvroException where untrusted bytes come in, and switch over it to decide what to do. The example makes each of the six failures happen once. 

import 'dart:convert';
import 'dart:typed_data';

import 'package:avro/avro.dart';

String explain(AvroException e) => switch (e) {
  SchemaParseException(:final path) => 'bad schema at $path',
  ResolutionException(:final path) => 'schemas do not resolve at $path',
  DecodeException(:final offset) => 'bad bytes at offset $offset',
  EncodeException(:final path) => 'bad value at $path',
  LimitExceededException(:final limit) => 'over $limit',
  UnsupportedCompressionException(:final compression) => 'cannot read $compression files',
};

/// A container file header whose blocks claim to be compressed with snappy.
Uint8List snappyFile() {
  final metadata = AvroCodec(writer: Schema.parse('{"type": "map", "values": "bytes"}'));
  return Uint8List.fromList([
    ...ascii.encode('Obj'), 1,
    ...metadata.encode({
      'avro.codec': utf8.encode('snappy'),
      'avro.schema': utf8.encode('"string"'),
    }),
    ...List.filled(16, 0),
  ]);
}

void main() {
  final user = Schema.parse('''
  {"type": "record", "name": "User", "fields": [{"name": "age", "type": "int"}]}
  ''');
  final codec = AvroCodec(writer: user);

  final failures = <void Function()>[
    () => Schema.parse('{"type": "record", "name": "User", "fields": [{"name": "age"}]}'),
    () => AvroCodec(writer: user, reader: Schema.parse('"string"')),
    () => codec.decode(Uint8List.fromList([0x80])),
    () => codec.encode({'age': 'old'}),
    () => Schema.parse('"int"', limits: const AvroLimits(maxSchemaBytes: 3)),
    () => AvroFileReader(snappyFile()),
  ];
  for (final fail in failures) {
    try {
      fail();
    } on AvroException catch (e) {
      print(explain(e));
    }
  }
}

Errors that are not AvroException

A wrong argument or a wrong use of an object is a bug in the calling code, not bad input, and throws one of Dart's own errors. Do not catch these at a boundary; fix the call.

Error Thrown when
ArgumentErrorAvroFileWriter gets a metadata key starting with avro., a syncMarker that is not 16 bytes, or a schemaJson with another canonical form than the codec's writer schema
ArgumentErrorcrc64FromBytes gets anything but 8 bytes
StateError add, flush or close is called on an AvroFileWriter that is closed
 
import 'dart:typed_data';

import 'package:avro/avro.dart';

void main() {
  final codec = AvroCodec(writer: Schema.parse('"string"'));
  try {
    AvroFileWriter(codec, metadata: {'avro.owner': Uint8List(0)});
  } on ArgumentError catch (e) {
    print(e.message);
  }

  final writer = AvroFileWriter(codec)..add('one');
  writer.close();
  try {
    writer.add('two');
  } on StateError catch (e) {
    print(e.message);
  }
}
