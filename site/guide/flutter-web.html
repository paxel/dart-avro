The package runs in the browser when the app is compiled to WebAssembly with dart2wasm. It does not run when it is compiled to JavaScript with dart2js, and says so at the first call instead of giving wrong results.

Build with WebAssembly

Avro's long is 64 bits, and the package holds it in a Dart int. With dart2wasm an int is 64-bit, as on the VM and AOT, so the package behaves there as on the VM: the codecs, JSON, single-object encoding, container files in every compression, fingerprints, sort order and compatibility. Build a Flutter web app with: 

flutter build web --wasm

The tests that need no dart:io run in CI in Chrome under dart2wasm, with dart test -p chrome --compiler dart2wasm -t web.

The JavaScript fallback

Even with --wasm, Flutter also compiles the app to JavaScript, and loads that build in a browser without WebAssembly GC, or one that its wasmAllowList does not enable. There the package throws as under dart2js. See Support for WebAssembly in the Flutter documentation for which browsers get which build.

What dart2js does

With dart2js an int is a JavaScript number: exact only up to 253, with 32-bit bit operations. Avro's long, its zig-zag varints and CRC-64-AVRO would go silently wrong. So, under dart2js, these throw an UnsupportedError at once, before doing any work; printed, it reads: 

Unsupported operation: avro needs 64-bit integers: compile for the web with dart2wasm
Under dart2js APIs
Throw UnsupportedErrorCreating an AvroCodec or a TypedCodec; creating an AvroFileReader, an AvroFileWriter or an AvroFileStreamWriter, and AvroFileStreamReader.open; crc64Avro, crc64ToBytes, crc64FromBytes and Schema.crc64; and so SingleObjectHeader.parse, once the bytes have the marker and the length of a header
Stay usable Schema.parse and the schema tree, canonicalForm, md5 and sha256

Without a codec nothing is encoded or decoded, so an app built with dart2js can parse and fingerprint schemas, but not read or write data. These run the same everywhere: 

import 'package:avro/avro.dart';

void main() {
  // Usable under dart2js too: parsing, the canonical form, MD5 and SHA-256.
  final schema = Schema.parse('''
  {"type": "record", "name": "Memo", "namespace": "com.example",
   "fields": [{"name": "text", "type": "string"}]}
  ''');
  print(schema.canonicalForm);
  String hex(List<int> bytes) =>
      bytes.map((b) => b.toRadixString(16).padLeft(2, '0')).join();
  print(hex(schema.md5));
  print(hex(schema.sha256));
}

DEFLATE on the web

The VM and AOT compress and decompress deflate container files with the zlib of dart:io. The web has no dart:io, so there the package uses the pure-Dart DEFLATE of archive, which it already depends on for bzip2, xz and zstandard. A conditional import chooses between the two; your code does not change, and the files are read and written with the same checks and the same limits. The other compressions are pure Dart on every platform. 

import 'package:avro/avro.dart';

void main() {
  // The same code on the VM, AOT and dart2wasm: deflate through dart:io's zlib on the
  // VM and AOT, through archive's pure-Dart DEFLATE on the web.
  final codec = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "Line", "fields": [{"name": "text", "type": "string"}]}
  '''));
  final writer = AvroFileWriter(codec, compression: 'deflate');
  for (var i = 0; i < 3; i++) {
    writer.add({'text': 'line $i'});
  }
  final file = writer.close();

  final reader = AvroFileReader(file);
  print(reader.header.compression);
  reader.records().forEach(print);
}

In a browser there are no files to open: read the bytes of a container file from an HTTP response or a file picker as a Uint8List, and give them to AvroFileReader, or a byte stream to AvroFileStreamReader.open.
