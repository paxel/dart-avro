A container file holds many records of one schema, with the schema in its header. It is what other Avro libraries call an .avro file. AvroFileWriter writes one in memory and AvroFileReader reads one from memory.

The layout

A file starts with its header: the magic bytes Obj and 1, the metadata, and a 16-byte sync marker. The metadata maps string keys to bytes; avro.schema holds the writer schema as JSON text and avro.codec the compression. Blocks follow: each one is a count of records, their size, the records compressed together, and the sync marker.

Write a file

AvroFileWriter(codec, …) writes records with the codec's writer schema. add(record) encodes one record into the current block, flush() ends the block, and close() ends the last block and returns the whole file as a Uint8List. After close, the writer throws StateError.

Argument Default What it does
compression'null' 'null' or 'deflate' (raw DEFLATE, as the specification says); anything else throws UnsupportedCompressionException
metadata none Your entries, Map<String, Uint8List>, written first and in your order; a key starting with avro. throws ArgumentError
schemaJson the writer schema's jsonTextThe text of avro.schema, written exactly as given; it must have the canonical form of the codec's writer schema, or it throws ArgumentError
syncMarker 16 random bytes The sync marker; any other length than 16 throws ArgumentError
blockSize 64 KiB The size before compression at which a block ends by itself, after the record that reaches it

The header is written in this order: your metadata, then avro.codec, always, even for null, then avro.schema. add throws EncodeException for a record that does not fit the schema, and leaves the file as it was, so you can skip the record and go on. 

import 'dart:convert';
import 'dart:typed_data';

import 'package:avro/avro.dart';

void main() {
  final codec = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "Event", "fields": [
    {"name": "id", "type": "long"}, {"name": "kind", "type": "string"}
  ]}
  '''));

  final writer = AvroFileWriter(
    codec,
    compression: 'deflate',
    metadata: {'app.name': utf8.encode('example'), 'app.version': utf8.encode('1')},
    syncMarker: Uint8List.fromList(List.generate(16, (i) => i)),
  );
  writer.add({'id': 1, 'kind': 'start'});
  try {
    writer.add({'id': 2}); // no kind: rejected, the file is unchanged
  } on EncodeException catch (e) {
    print(e);
  }
  writer.flush(); // ends the first block
  writer.add({'id': 3, 'kind': 'stop'});
  final file = writer.close();

  final reader = AvroFileReader(file);
  print(reader.header.metadata.keys.toList());
  print(reader.header.compression);
  print(reader.header.syncMarker);
  print(reader.records().toList());
}

With the random default sync marker, no two files are alike, even with the same records. Pass a fixed syncMarker when you need byte-exact files, for tests or for published example files.

Read the header first

AvroFileReader(bytes, limits:) reads the header when it is made, and nothing else. So you can look at the metadata, the schema and the compression before you decode any record. The constructor throws DecodeException if the bytes are not a container file, and UnsupportedCompressionException if the blocks use a compression other than null and deflate, such as snappy.

header. Holds
metadata Every entry, avro.schema and avro.codec included, in the order of the file, as Uint8List
schemaJsonThe text of avro.schema
compressionnull or deflate; null when the file has no avro.codec
syncMarkerThe 16 bytes that end every block

Read the records

records() returns a lazy Iterable. Each time the iteration reaches a block, that block is checked against its sync marker, decompressed, and decoded record by record; only one decompressed block is held at a time. Everything that can go wrong in the blocks is thrown while you iterate, after the records before it have been returned: DecodeException for a malformed block and LimitExceededException for a block over the limits.

Without an argument, records() parses the file's own schema, with the reader's limits, when the iteration starts; a schema text that is not valid throws SchemaParseException then. Each iteration starts again from the first block.

Decode with your own codec

records(codec) decodes with a codec you pass. The codec's writer schema must be the schema the file was written with: the reader does not compare them, and a codec of another schema reads garbage or throws. There are two safe ways to get one:

  • Parse header.schemaJson as the writer schema, and pass your schema as the reader, so that the file's schema is resolved against yours.
  • If you expect files of one known schema, compare the canonical form of header.schemaJson with your schema's, reject the file if they differ, and decode with your own codec.

The second way suits files from untrusted senders: the file's schema is parsed once to compare it, and the records are decoded with a codec you made and checked. 

import 'dart:typed_data';

import 'package:avro/avro.dart';

final expected = Schema.parse('''
{"type": "record", "name": "Event", "fields": [
  {"name": "id", "type": "long"}, {"name": "kind", "type": "string"}
]}
''');
final codec = AvroCodec(writer: expected);

List<Object?> readEvents(Uint8List bytes) {
  final reader = AvroFileReader(bytes);
  final written = Schema.parse(reader.header.schemaJson);
  if (written.canonicalForm != expected.canonicalForm) {
    throw FormatException('not a file of events: ${reader.header.schemaJson}');
  }
  return reader.records(codec).toList();
}

void main() {
  // Another program wrote the file, with its own spacing and a doc.
  final other = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "Event", "doc": "One event.",
   "fields": [{"name": "id", "type": "long"}, {"name": "kind", "type": "string"}]}
  '''));
  final writer = AvroFileWriter(other)
    ..add({'id': 1, 'kind': 'start'})
    ..add({'id': 2, 'kind': 'stop'});
  print(readEvents(writer.close()));

  final strings = AvroFileWriter(AvroCodec(writer: Schema.parse('"string"')))..add('x');
  try {
    readEvents(strings.close());
  } on FormatException catch (e) {
    print(e.message);
  }
}
[{id: 1, kind: start}, {id: 2, kind: stop}]
not a file of events: "string"

A codec passed to records keeps its own limits for the values it decodes; the reader's limits bound the blocks.

Storing a file

Both classes work on bytes in memory. Read and write the bytes with dart:io, for example File('events.avro').readAsBytesSync(). The whole file is in memory while it is read; of its records, only one decompressed block at a time.
