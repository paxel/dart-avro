Before a new schema goes live, you want to know whether it can read what the old one wrote. checkCompatibility answers that from the two schemas alone, with every reason it finds, not only the first.

Checking two schemas

checkCompatibility(reader:, writer:) checks whether data of the writer schema can be read as the reader schema by the schema resolution of AvroCodec. It returns a SchemaCompatibility:

  • isCompatible: whether every datum of the writer schema can be read as the reader schema.
  • incompatibilities: every Incompatibility found, in the order of the schemas; empty if compatible.

Each Incompatibility has its kind, a message in words, and two paths, readerPath and writerPath. 

import 'package:avro/avro.dart';

void main() {
  final writer = Schema.parse('''
  {"type": "record", "name": "Memo", "fields": [
    {"name": "text", "type": "string"},
    {"name": "stars", "type": "int"},
    {"name": "colour", "type": {"type": "enum", "name": "Colour", "symbols": ["RED", "GREEN", "BLUE"]}},
    {"name": "tags", "type": {"type": "array", "items": "string"}}
  ]}
  ''');
  final reader = Schema.parse('''
  {"type": "record", "name": "Memo", "fields": [
    {"name": "text", "type": "string"},
    {"name": "stars", "type": "double"},
    {"name": "colour", "type": {"type": "enum", "name": "Colour", "symbols": ["RED", "GREEN"]}},
    {"name": "tags", "type": {"type": "array", "items": "long"}},
    {"name": "author", "type": "string"}
  ]}
  ''');

  final result = checkCompatibility(reader: reader, writer: writer);
  print(result.isCompatible);
  for (final i in result.incompatibilities) {
    print('${i.kind.name}: ${i.readerPath} / ${i.writerPath}');
    print('  ${i.message}');
  }

  // The other way round: double does not resolve to int, nor long to string.
  print(checkCompatibility(reader: writer, writer: reader).incompatibilities.length);
}

  the reader enum lacks the writer symbols BLUE and has no default

  string does not resolve to long

  the reader field "author" has no default and the writer lacks it

The int read as double is a promotion and no incompatibility.

The kinds

IncompatibilityKind is named after SchemaIncompatibilityType of Apache Avro for Java, where one matches:

Kind When
nameMismatch A named type of the writer has neither the reader's name nor one of its aliases
fixedSizeMismatch The writer's fixed has another size than the reader's
missingEnumSymbols The writer's enum has symbols the reader's lacks, and the reader's has no default
readerFieldMissingDefaultValue A field of the reader's record that the writer's lacks has no default
typeMismatch The writer's type neither is the reader's nor promotes to it
missingUnionBranch No branch of the reader's union takes the writer's type, or the writer's union has no branch at all
decimalMismatch The writer's and the reader's decimal differ in precision or scale; Java has no such kind

The two paths

readerPath says where the incompatibility is in the reader schema, and writerPath where it is in the writer schema. Both are written as the paths of ResolutionException: the name of the schema, then .field for a field, [] for the items of an array, {} for the values of a map and <branch> for a branch of a union. Each names only the fields and branches of its own schema, so they differ where the schemas do: a record renamed with an alias, a field matched by an alias, a field only one side has, a branch of the writer's union. 

import 'package:avro/avro.dart';

void main() {
  final writer = Schema.parse('''
  {"type": "record", "name": "com.example.Memo", "fields": [
    {"name": "text", "type": "string"},
    {"name": "id", "type": {"type": "fixed", "name": "Id", "size": 16}}
  ]}
  ''');
  final reader = Schema.parse('''
  {"type": "record", "name": "com.example.Note", "aliases": ["com.example.Memo"], "fields": [
    {"name": "body", "type": "int", "aliases": ["text"]},
    {"name": "id", "type": {"type": "fixed", "name": "Id", "size": 8}}
  ]}
  ''');

  for (final i in checkCompatibility(reader: reader, writer: writer).incompatibilities) {
    print(i);
  }

  // A codec for the two stops at the first problem.
  try {
    AvroCodec(writer: writer, reader: reader);
  } on ResolutionException catch (e) {
    print(e);
  }
}
Incompatibility(typeMismatch at com.example.Note.body, writer com.example.Memo.text: string does not resolve to int)
Incompatibility(fixedSizeMismatch at com.example.Note.id, writer com.example.Memo.id: the writer fixed has 16 bytes, the reader fixed 8)
ResolutionException at com.example.Note.body: string does not resolve to int

What fails only for some data

The check agrees with AvroCodec(writer:, reader:): where the constructor throws ResolutionException, the result is incompatible. It also reports two cases for which the codec can still be made, because only some data fails, and that data then throws ResolutionException from decode:

  • missingEnumSymbols: a datum holding a writer symbol the reader lacks, when the reader's enum has no default. Every other symbol reads.
  • Any incompatibility inside a branch of the writer's union, recognisable by the <branch> in its writerPath, such as Event.payload<int>: a datum in that branch. The other branches read. Only when no branch of the writer's union resolves does the codec throw at once.
import 'package:avro/avro.dart';

void main() {
  final writer = Schema.parse('''
  {"type": "record", "name": "Event", "fields": [
    {"name": "colour", "type": {"type": "enum", "name": "Colour", "symbols": ["RED", "BLUE"]}},
    {"name": "payload", "type": ["null", "string", "int"]}
  ]}
  ''');
  final reader = Schema.parse('''
  {"type": "record", "name": "Event", "fields": [
    {"name": "colour", "type": {"type": "enum", "name": "Colour", "symbols": ["RED"]}},
    {"name": "payload", "type": ["null", "string"]}
  ]}
  ''');

  for (final i in checkCompatibility(reader: reader, writer: writer).incompatibilities) {
    print('${i.kind.name} at ${i.readerPath}, writer ${i.writerPath}');
  }

  // The codec can still be made: only some data fails.
  final codec = AvroCodec(writer: writer, reader: reader);
  final writing = AvroCodec(writer: writer);
  print(codec.decode(writing.encode({'colour': 'RED', 'payload': 'hi'})));
  for (final value in [
    {'colour': 'BLUE', 'payload': null},
    {'colour': 'RED', 'payload': 7},
  ]) {
    try {
      codec.decode(writing.encode(value));
    } on ResolutionException catch (e) {
      print(e);
    }
  }
}

missingUnionBranch at Event.payload, writer Event.payload<int>
{colour: RED, payload: hi}
ResolutionException at $.colour: the writer symbol "BLUE" is not in Colour, which has no default
ResolutionException at $.payload: the writer wrote a branch that does not resolve: ResolutionException at Event.payload<int>: no branch of the reader union null, string matches int

So use checkCompatibility to decide whether a schema may replace another, and the codec to read the data: an incompatible result does not mean that no datum can be read, and data written by a compatible writer schema still throws DecodeException if its bytes are not a valid encoding.
