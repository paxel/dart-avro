Single-object encoding sends one value together with the fingerprint of the schema it was written with, so the receiver can tell which schema to read it with. It suits messages, queue entries and database cells, where a container file would be too much.

The format

A single-object message is three parts, back to back:

Bytes Content
2 The marker C3 01
8 The CRC-64-AVRO fingerprint of the writer schema, little-endian
the restThe datum, in the binary encoding

The first two parts are the single-object header. codec.encodeSingleObject(value) writes the whole message with the codec's writer schema, and codec.decodeSingleObject(bytes) reads it back. 

import 'package:avro/avro.dart';

String hex(List<int> bytes) =>
    bytes.map((b) => b.toRadixString(16).padLeft(2, '0')).join(' ');

void main() {
  final codec = AvroCodec(writer: Schema.parse('"string"'));

  final message = codec.encodeSingleObject('hi');
  print(hex(message));
  print(hex(crc64ToBytes(codec.writer.crc64)));
  print(codec.decodeSingleObject(message));
}
c3 01 c7 03 45 63 72 48 01 8f 04 68 69
c7 03 45 63 72 48 01 8f
hi

Choose the codec by fingerprint

SingleObjectHeader.parse(bytes) reads the header alone, without decoding the datum. Its fingerprint is the CRC-64-AVRO int, the same value as schema.crc64, so it can key a map of codecs. Its payload is the datum after the header, a view of the bytes you passed.

A receiver keeps one codec per writer schema it accepts. When the writer schemas are older versions of the receiver's own schema, each codec resolves its version to the current one, so every message comes out in one shape. Which fingerprints to accept is your decision: the package keeps no registry. 

import 'package:avro/avro.dart';

void main() {
  final v1 = Schema.parse('''
  {"type": "record", "name": "Ping", "fields": [{"name": "from", "type": "string"}]}
  ''');
  final v2 = Schema.parse('''
  {"type": "record", "name": "Ping", "fields": [
    {"name": "from", "type": "string"},
    {"name": "hops", "type": "int", "default": 0}
  ]}
  ''');

  // Every writer schema the receiver accepts, read as the current v2.
  final codecs = {
    for (final writer in [v1, v2]) writer.crc64: AvroCodec(writer: writer, reader: v2),
  };

  final messages = [
    AvroCodec(writer: v1).encodeSingleObject({'from': 'old app'}),
    AvroCodec(writer: v2).encodeSingleObject({'from': 'new app', 'hops': 2}),
  ];

  for (final message in messages) {
    final header = SingleObjectHeader.parse(message);
    final codec = codecs[header.fingerprint];
    if (codec == null) {
      print('unknown schema ${header.fingerprint}');
      continue;
    }
    print(codec.decodeSingleObject(message));
  }
}
{from: old app, hops: 0}
{from: new app, hops: 2}

codec.decode(header.payload) decodes the same datum, but does not check the fingerprint again; decodeSingleObject does.

What is rejected

SingleObjectHeader.parse throws DecodeException if the bytes are shorter than the 10 bytes of the header or do not start with C3 01. decodeSingleObject throws the same, and also if the fingerprint is not the one of the codec's writer schema; the message names the fingerprint in hexadecimal. After the header, the datum is decoded as by decode: invalid bytes, or bytes left over, throw DecodeException. 

import 'package:avro/avro.dart';

void main() {
  final strings = AvroCodec(writer: Schema.parse('"string"'));
  final longs = AvroCodec(writer: Schema.parse('"long"'));

  for (final bytes in [
    strings.encode('hi'), // no header at all
    strings.encodeSingleObject('hi'), // the header names another schema
  ]) {
    try {
      longs.decodeSingleObject(bytes);
    } on DecodeException catch (e) {
      print(e);
    }
  }
}
DecodeException at byte 0: single-object encoding needs 10 bytes of header, got 3
DecodeException at byte 2: the fingerprint 0x8f014872634503c7 is not the writer schema's

The fingerprint is of the canonical form, which leaves out documentation, aliases, defaults and logical types. Two schemas that differ only in those share a fingerprint, and a codec accepts the messages of both.
