Avro has a JSON encoding beside the binary one, which tools show and people read. codec.encodeJson(value) writes a value as JSON text and codec.decodeJson(text) reads it back, with the same values, checks and schema resolution as encode and decode.

Write and read JSON

encodeJson takes the same plain values as encode and returns a compact String; indent:, such as two spaces, indents it. decodeJson returns the values decode would return. Each Avro type is written the way the specification writes a field default:

  • Records and maps are JSON objects, arrays are JSON arrays, enums are their symbol as a string.
  • bytes and fixed are strings of the code points 0 to 255, one per byte.
  • A logical type is written as its underlying type: a timestamp-millis as its long.
  • A float is written with the fewest digits that read back as the same float, so 0.1 stays 0.1.
  • NaN, Infinity and -Infinity, which JSON has no numbers for, are the strings "NaN", "Infinity" and "-Infinity", both ways.
  • A union value is null, or an object with one key, the branch, around the value: {"double": 21.5}.
import 'dart:typed_data';

import 'package:avro/avro.dart';

void main() {
  final codec = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "Reading", "namespace": "com.example", "fields": [
    {"name": "sensor", "type": "string"},
    {"name": "value", "type": ["null", "int", "double"]},
    {"name": "ratio", "type": "float"},
    {"name": "raw", "type": "bytes"},
    {"name": "at", "type": {"type": "long", "logicalType": "timestamp-millis"}}
  ]}
  '''));

  final json = codec.encodeJson({
    'sensor': 'kitchen',
    'value': 21.5,
    'ratio': 0.1,
    'raw': Uint8List.fromList([0, 65, 255]),
    'at': DateTime.utc(2025, 11, 15, 10),
  });
  print(json);
  print(codec.decodeJson(json));

  print(codec.encodeJson({
    'sensor': 'hall',
    'value': null,
    'ratio': double.nan,
    'raw': Uint8List(0),
    'at': DateTime.utc(2025),
  }, indent: '  '));
}
{"sensor":"kitchen","value":{"double":21.5},"ratio":0.1,"raw":"\u0000Aÿ","at":1763200800000}
{sensor: kitchen, value: 21.5, ratio: 0.10000000149011612, raw: [0, 65, 255], at: 2025-11-15 10:00:00.000Z}
{
  "sensor": "hall",
  "value": null,
  "ratio": "NaN",
  "raw": "",
  "at": 1735689600000
}

The decoded ratio is the double nearest to the float, as decode returns it too; the JSON text has the short form.

Union branches

encodeJson names a branch as Branch does: by its full name for a named type, such as com.example.Click, and by its type name otherwise: string, array, map. That is what Apache Avro's Java implementation writes. The branch is chosen as for encode, so a value that more than one branch fits needs a Branch.

decodeJson accepts those names, and also the simple name of a named type, such as Scroll, when no other branch of the union has that simple name. A key the union does not have, or a simple name of two branches, throws DecodeException. {"null": null} is read as the null branch, as Java reads it. 

import 'package:avro/avro.dart';

void main() {
  final codec = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "Event", "namespace": "com.example", "fields": [
    {"name": "payload", "type": [
      {"type": "record", "name": "Click", "fields": [{"name": "x", "type": "int"}]},
      {"type": "record", "name": "com.other.Click", "fields": [{"name": "x", "type": "int"}]},
      {"type": "record", "name": "Scroll", "fields": [{"name": "dy", "type": "int"}]},
      "string"
    ]}
  ]}
  '''));

  // Written with the full name, as Java writes it.
  print(codec.encodeJson({'payload': const Branch('com.example.Click', {'x': 3})}));

  // Read with the full name, the type name, or a simple name that only one branch has.
  for (final json in [
    '{"payload": {"com.example.Scroll": {"dy": 2}}}',
    '{"payload": {"string": "hi"}}',
    '{"payload": {"Scroll": {"dy": 2}}}',
    '{"payload": {"Click": {"x": 3}}}',
    '{"payload": {"dy": 2}}',
  ]) {
    try {
      print(codec.decodeJson(json));
    } on DecodeException catch (e) {
      print(e);
    }
  }
}
{"payload":{"com.example.Click":{"x":3}}}
{payload: {dy: 2}}
{payload: hi}
{payload: {dy: 2}}
DecodeException at byte 0 ($.payload): "Click" names more than one branch of the union; use the full name of one of com.example.Click, com.other.Click, com.example.Scroll, string
DecodeException at byte 0 ($.payload): the union has no branch "dy"; it has com.example.Click, com.other.Click, com.example.Scroll, string

decodeJson returns the plain value of a union, like decode; a codec made with decodeBranches: true returns a Branch, see Decoding into Branch.

Resolution and strict input

The JSON text is a value of the codec's writer schema. decodeJson reads it as the reader schema, by schema resolution, exactly as decode reads binary data: promotions apply, and fields the writer schema lacks get the reader's defaults.

The text itself must fit the writer schema exactly. A record needs every field of the writer schema and no other, since the writer's defaults are not filled in; an int or long must be a JSON integer, and an int must fit 32 bits. Anything else throws DecodeException, with offset 0 and the path of the value in the JSON. Text that is not JSON throws it without a path. JSON that repeats a key keeps its last value; it cannot be detected. 

import 'package:avro/avro.dart';

void main() {
  final v1 = Schema.parse('''
  {"type": "record", "name": "User", "fields": [
    {"name": "name", "type": "string"}, {"name": "age", "type": "int"}
  ]}
  ''');
  final v2 = Schema.parse('''
  {"type": "record", "name": "User", "fields": [
    {"name": "name", "type": "string"}, {"name": "age", "type": "long"},
    {"name": "email", "type": ["null", "string"], "default": null}
  ]}
  ''');

  // JSON of the writer schema v1, read as v2: the age promoted, the email defaulted.
  final codec = AvroCodec(writer: v1, reader: v2);
  print(codec.decodeJson('{"name": "Ada", "age": 36}'));

  // The JSON must be a value of the writer schema, exactly.
  for (final json in [
    '{"name": "Ada"}',
    '{"name": "Ada", "age": 36, "email": null}',
    '{"name": "Ada", "age": 3000000000}',
    '{"name": "Ada", "age": 36.0}',
    '{"name": "Ada", "age": 36',
  ]) {
    try {
      codec.decodeJson(json);
    } on DecodeException catch (e) {
      print(e);
    }
  }
}
{name: Ada, age: 36, email: null}
DecodeException at byte 0 ($): the field "age" is missing
DecodeException at byte 0 ($): "email" is not a field of User
DecodeException at byte 0 ($.age): 3000000000 does not fit 32 bits
DecodeException at byte 0 ($.age): expected an integer for int, got the number 36.0
DecodeException at byte 0: not JSON: Unexpected end of input

encodeJson throws EncodeException for a value that does not fit, as encode does. The codec's maxValueDepth also bounds the nesting of the JSON text, checked before the text is parsed; see Untrusted input and limits.

Generated classes

TypedCodec has encodeJson and decodeJson too, for the classes of code generation: encodeJson writes the type's own schema, and decodeJson reads JSON of the codec's writer schema as the type.
