Data written with one schema can be read as another, by the rules of the Avro specification. AvroCodec(writer:, reader:) works out how, once, and then decodes every datum of the writer schema into the shape of the reader schema.

One codec per pair of schemas

The writer schema is the one the data was encoded with; the reader schema is the one your code expects. The constructor compiles the resolution of the two and throws ResolutionException if they cannot resolve, before any data is read. Make the codec once and keep it; decode then follows the compiled plan.

encode always writes with the writer schema; the reader schema plays no part in it. Without reader:, or with the same object as the writer, the codec decodes the writer schema as it is. 

import 'package:avro/avro.dart';

void main() {
  final v1 = Schema.parse('''
  {"type": "record", "name": "Reading", "namespace": "com.example", "fields": [
    {"name": "sensor", "type": "string"},
    {"name": "temp", "type": "int"},
    {"name": "unit", "type": {"type": "enum", "name": "Unit", "symbols": ["C", "F", "K"]}},
    {"name": "debug", "type": "string"}
  ]}
  ''');
  final v2 = Schema.parse('''
  {"type": "record", "name": "Reading", "namespace": "com.example", "fields": [
    {"name": "device", "type": "string", "aliases": ["sensor"]},
    {"name": "temp", "type": "double"},
    {"name": "unit", "type": {"type": "enum", "name": "Unit", "symbols": ["C", "F", "OTHER"],
                              "default": "OTHER"}},
    {"name": "site", "type": "string", "default": "unknown"}
  ]}
  ''');

  final writer = AvroCodec(writer: v1);
  final old = [
    writer.encode({'sensor': 'a1', 'temp': 21, 'unit': 'C', 'debug': 'x'}),
    writer.encode({'sensor': 'b2', 'temp': 280, 'unit': 'K', 'debug': 'y'}),
  ];

  final upgrade = AvroCodec(writer: v1, reader: v2);
  for (final bytes in old) {
    print(upgrade.decode(bytes));
  }
}
{device: a1, temp: 21.0, unit: C, site: unknown}
{device: b2, temp: 280.0, unit: OTHER, site: unknown}

The example shows every rule of records at once: sensor is read into device by its alias, temp is promoted from int to double, the unknown symbol K becomes the reader's default OTHER, debug is skipped, and site takes its default.

Which schemas match

Two schemas resolve when they match at the top, and their parts resolve in turn:

Writer Reader Matches when
a primitive the same primitive always
int long, float, doublealways: a promotion
long float, double always: a promotion
float double always: a promotion
string bytes always: the UTF-8 bytes
bytes string always; bytes that are not UTF-8 throw DecodeException when decoded
record record the names match
enum enum the names match
fixed fixed the names match and the sizes are equal
array array the items resolve
map map the values resolve
a union anything see Unions
anything a union see Unions

Nothing else matches: a long is never read as an int, nor a double as a float.

Named types match on their name without the namespace, as the specification says, or when the reader type lists the writer's full name, or its name, among its aliases. A reader that renames old.Reading to new.Measurement says "aliases": ["old.Reading"].

The reader's logical type applies to what is read. A long written as a plain number is read as a DateTime if the reader says timestamp-millis; a decimal written with a logical type is read as plain bytes if the reader has none. Two decimals must agree in precision and scale, or the schemas do not resolve.

Records: fields by name and alias

  • Each writer field is matched to the reader field of the same name, or else to the first reader field that lists the writer field's name among its aliases. The order of the fields may differ.
  • A writer field with no match in the reader is read and dropped.
  • A reader field with no match in the writer takes its default. Each decoded record gets its own copy of the default, so changing one record's list does not change the next.
  • A reader field with no match and no default makes the schemas unresolvable: the constructor throws.

The decoded map has the reader's fields, in the reader's order.

Enums

A writer symbol is read as the reader symbol of the same name. A writer symbol the reader does not have becomes the reader's default. Without a reader default, such a symbol cannot be read; the codec is still made, because the data may never hold it, and decode throws ResolutionException when it does.

Unions

  • Writer union. Each writer branch is resolved against the reader schema on its own. If no branch resolves, the constructor throws. If only some resolve, the codec is made, and decode throws ResolutionException for a datum of a branch that does not.
  • Reader union, writer not a union. The writer schema is read as the reader branch that Apache Avro's Java implementation picks: first a branch of the same type, or of the same full name for a named type; then the first record that resolves, preferring the same short name; then the first promotion of the table above; then any other match, such as a name found by alias. If no branch matches, the constructor throws. So an int read as ["null", "double", "int"] stays an int, but read as ["null", "double", "long"] it becomes a double, the first promotion in the union's order.
  • Both unions. Each writer branch is read as the reader branch picked the same way.
import 'package:avro/avro.dart';

void main() {
  final writer = Schema.parse('["null", "string", "int"]');
  final data = AvroCodec(writer: writer);

  // int resolves against long; null and string do not, but only the datum decides.
  final asLong = AvroCodec(writer: writer, reader: Schema.parse('"long"'));
  print(asLong.decode(data.encode(5)));
  try {
    asLong.decode(data.encode('five'));
  } on ResolutionException catch (e) {
    print(e.message);
  }

  // A plain int read as a union: the branch of the same type first, then a promotion.
  final widen = AvroCodec(
    writer: Schema.parse('"int"'),
    reader: Schema.parse('["null", "double", "int"]'),
  );
  print(widen.decode(AvroCodec(writer: Schema.parse('"int"')).encode(5)));
  final promote = AvroCodec(
    writer: Schema.parse('"int"'),
    reader: Schema.parse('["null", "double", "long"]'),
  );
  print(promote.decode(AvroCodec(writer: Schema.parse('"int"')).encode(5)));
}
5
the writer wrote a branch that does not resolve: ResolutionException at long<string>: string does not resolve to long

A codec made with decodeBranches: true returns the value of a reader union with two or more non-null branches as a Branch named after the reader branch it was read as, also when the writer schema is not a union, and also for a default the reader schema fills in. See Decoding into Branch.

What throws, and when

ResolutionException has a path. From the constructor, it points into the schemas, such as Reading.temp, or Reading.tags[] for the items of an array. From decode, it is the path of the value, such as $.unit.

Problem Thrown by
The types do not match, such as long read as int the constructor
Two named types have different names and no alias joins them the constructor
Two fixed types differ in size the constructor
Two decimals differ in precision or scale the constructor
A reader field has no default and the writer lacks it the constructor
No branch of a writer union resolves, or no reader branch matches the writerthe constructor
A writer symbol is unknown to a reader enum without a default decode, for a datum with that symbol
A datum is of a writer branch that does not resolve decode, for a datum of that branch
 
import 'package:avro/avro.dart';

void main() {
  final pairs = [
    ('"long"', '"int"'),
    ('{"type": "record", "name": "A", "fields": []}',
     '{"type": "record", "name": "B", "fields": []}'),
    ('{"type": "record", "name": "A", "fields": []}',
     '{"type": "record", "name": "A", "fields": [{"name": "id", "type": "long"}]}'),
    ('{"type": "record", "name": "A", "fields": [{"name": "tags", "type": {"type": "array", "items": "string"}}]}',
     '{"type": "record", "name": "A", "fields": [{"name": "tags", "type": {"type": "array", "items": "int"}}]}'),
  ];
  for (final (writer, reader) in pairs) {
    try {
      AvroCodec(writer: Schema.parse(writer), reader: Schema.parse(reader));
    } on ResolutionException catch (e) {
      print(e);
    }
  }

  // An enum without a default resolves; only an unknown symbol fails, while decoding.
  final colours = Schema.parse('{"type": "enum", "name": "C", "symbols": ["RED", "BLUE"]}');
  final codec = AvroCodec(
    writer: colours,
    reader: Schema.parse('{"type": "enum", "name": "C", "symbols": ["RED"]}'),
  );
  final data = AvroCodec(writer: colours);
  print(codec.decode(data.encode('RED')));
  try {
    codec.decode(data.encode('BLUE'));
  } on ResolutionException catch (e) {
    print(e);
  }
}

ResolutionException at B: A does not resolve to B
ResolutionException at A.id: the reader field "id" has no default and the writer lacks it
ResolutionException at A.tags[]: string does not resolve to int

The resolution does not check the data: bytes that are not a valid encoding of the writer schema still throw DecodeException, and the limits of the codec apply as they do without a reader schema.
