Every term the documentation uses, defined once. The vocabulary itself is kept in CONTEXT.md in the repository.

Schemas

Writer schema
The schema the data was encoded with.
Reader schema
The schema the caller wants the data in. The writer schema is resolved against it.
Resolution
The mapping from a writer schema to a reader schema, as the Avro specification defines it.
Canonical form
The Parsing Canonical Form of a schema, as the Avro specification defines it.
Fingerprint
A hash of a schema's canonical form: CRC-64-AVRO, MD5 or SHA-256.
Props
The attributes of a schema or a field that the Avro specification does not define. Not to be confused with metadata, which is the container file's.

Values

Codec
The object that encodes and decodes values for one writer schema and one reader schema: AvroCodec.
Datum
One encoded value of a schema.
Branch
The member of a union schema that a value belongs to. Branch(name, value) names it when encoding.

Container files

Container file
An Avro object container file: a header, then data blocks.
Header
The magic, the metadata and the sync marker at the start of a container file.
Metadata
The key-value map in a container file's header. Not to be confused with props, which are a schema's.
Block
A run of datums in a container file, compressed together and followed by the sync marker.
Sync marker
The 16 bytes that end every block of a container file.
Compression
How the blocks of a container file are compressed: null or deflate. The Avro specification calls it the file's codec; here "codec" is taken by the encoding object above.

Single-object encoding

Single-object header
The marker C3 01 and the writer schema's CRC-64-AVRO fingerprint that precede a datum in single-object encoding.
