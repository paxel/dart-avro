0.4.0 takes the package to the web, through dart2wasm, and adds two things Avro defines beside its formats: the sort order, and a compatibility check of two schemas. The codec also encodes and decodes several times as fast. This page says what changed for a reader rather than as a list; the changelog has the short version.

Flutter web through dart2wasm

The package runs on the web when compiled with dart2wasm, as flutter build web --wasm does, and pubspec.yaml lists web. deflate container files are read and written there through the pure-Dart DEFLATE of archive, with the same limits; the VM and AOT keep the zlib of dart:io. Compiled with dart2js, where an int cannot hold Avro's 64-bit values, the codecs, the container file readers and writers and the CRC-64 functions throw UnsupportedError("avro needs 64-bit integers: compile for the web with dart2wasm") instead of giving wrong results. See Flutter web.

Sort order

AvroCodec.compare compares two values, and AvroCodec.compareBytes two encodings without decoding them, by the Avro sort order: records field by field in each field's order, unions by branch, enums by symbol index, strings and bytes as unsigned bytes, logical values as their encoding. Maps have no order and throw ArgumentError. TypedCodec.compare does the same for generated classes. See Sort order.

Schema compatibility

checkCompatibility(reader:, writer:) reports, without data, every reason data of the writer schema cannot be read as the reader schema: each an Incompatibility with its kind, its path in both schemas and a message. It agrees with the resolution of AvroCodec, and also reports what fails only for some data, where a codec can still be made. See Schema compatibility.

A faster codec

AvroCodec compiles the writer schema once, at the first encode or decode, instead of walking it for every value. Binary encoding, and decoding when the reader schema is the writer schema, are 5 to 10 times as fast as before on the records of the benchmark suite, within 2× of Apache Avro for Java. Decoding with a reader schema that differs is as fast as before, and JSON and container files gain from the binary codec beneath them. Errors, their messages and paths, and the limits are unchanged. See Benchmarks.

Decoded records

A decoded record is still a Map<String, Object?> with its fields in schema order, and you may still change it, but it is no longer always a LinkedHashMap: when the reader schema is the writer schema, the codec decodes it into a map backed by a list of the field values. Code that checks for LinkedHashMap, or casts to it, must use Map instead.

Not in this release

The Avro IPC/RPC protocol, and the web compiled with dart2js.

Earlier: 0.3.0

0.3.0 covered the rest of Avro's data formats: every compression, the JSON encoding, and container files read from streams and written to sinks. Generated code got sealed classes for unions, and the generator became a library.

Breaking: sealed unions in generated code

dart run avro:generate maps a union with two or more non-null branches to a sealed class per place of use, named after the record and the field, with a final class per branch: EventPayload, EventPayloadClick, EventPayloadString. In 0.2.0 such a field was an Object? holding the plain value. Code generated by 0.2.0 must be regenerated, and the code that uses those fields updated: build the branch class where you passed the value, and switch over the field, which the analyzer checks for exhaustiveness. A record or enum named Branch now needs a --prefix. See Code generation.

Compressions

  • Container files are read and written with snappy, bzip2, xz and zstandard, besides null and deflate, all in pure Dart. snappy blocks carry their CRC32, zstandard blocks are written with a checksum, and xz blocks are written stored, without being compressed.
  • Decompression stops at maxBlockBytes and maxTotalBytes for every compression. The package depends on archive for bzip2, xz and zstandard.

The Compressions guide has the details.

JSON encoding

encodeJson and decodeJson, on AvroCodec and TypedCodec, write and read Avro's JSON encoding, compact or with indent:, and decode with schema resolution. A union value is null or {"<branch>": value} with the branch's full name, as Java writes it; NaN and the infinities are strings. See JSON encoding.

Streamed container files

AvroFileStreamReader.open reads a container file from a Stream<List<int>>, and AvroFileStreamWriter writes one to a StreamSink<List<int>>, with one block in memory at a time and the same bytes, checks and errors as AvroFileReader and AvroFileWriter. In the stream reader, maxBlockBytes also bounds a block's compressed size and the header. See Streamed container files.

Decoding into Branch

AvroCodec(decodeBranches: true) decodes the value of every union with two or more non-null branches as a Branch of its branch, so two records with the same fields can be told apart and a decoded value encodes back unchanged. TypedCodec decodes this way. See Values and unions.

The generator as a library

package:avro/generate.dart has generateDart, which takes schema texts as SchemaSources and returns the Dart source and the warnings as a GeneratedLibrary, or throws GenerateException, without files and without formatting. dart run avro:generate is a wrapper around it. A run of the command that warns and then fails prints only the error. See Code generation.

Not in 0.3.0

The Avro IPC/RPC protocol. The package did not run on Flutter web.

Earlier: 0.2.0

0.2.0 added code generation: typed Dart classes for your schemas, and a codec for them.

Code generation

  • dart run avro:generate <schemas…> -o <file> writes one Dart library from .avsc files: an immutable class for every record, with value equality, toString, copyWith and an avroType, and a Dart enum for every enum, each value with its Avro symbol.
  • A type defined in several files becomes one Dart type, and --prefix <namespace>=<Prefix> names the types of a namespace, for names such as DateTime that would clash with Dart's.
  • TypedCodec encodes and decodes those classes, with schema resolution of older data and single-object encoding; its avro codec writes and reads container files.

The Code generation guide shows it all.

Changes

  • A value read as a reader union now takes the branch that Apache Avro's Java implementation takes: the same type or full name first, then a record that resolves, then a promotion. An int read as ["null", "double", "int"] stays an int.
  • Every limit of AvroLimits throws LimitExceededException, also maxValueDepth on encode and maxZeroSizeItems in a container block, which threw EncodeException and DecodeException before.
  • AvroFileReader.records(codec) rejects a codec whose writer schema is not the file's, naming both fingerprints, before it decodes a record.
  • DecodeException.blockOffset says where the block of a failing record starts in a container file.
  • A string that is not a UUID, encoded as uuid, fails with a message that says so.

Earlier: 0.1.1 and 0.1.0

0.1.1 changed nothing in the package: it was the first version that the release workflow published to pub.dev. 0.1.0 was the first release, with:

Schemas

  • Schema.parse reads any Avro 1.12 schema into an immutable tree. The tree keeps the documentation, the aliases, the defaults and the attributes the specification does not define.
  • schema.canonicalForm is the Parsing Canonical Form. crc64, md5 and sha256 are its fingerprints. CRC-64-AVRO is an int; crc64ToBytes and crc64FromBytes convert it to and from its 8 little-endian bytes.

Values

  • AvroCodec encodes and decodes every primitive and complex type in Avro's binary encoding. Records and maps are Map<String, Object?>. Malformed input is rejected with an AvroException.
  • Every logical type of Avro 1.12 decodes to a Dart value: DateTime, Duration and String where they fit, and AvroDate, AvroLocalTimestamp, AvroTimestampNanos, AvroDecimal and AvroDuration where Dart has no type of its own.
  • A union value whose branch is ambiguous is written with Branch.

Schema resolution

AvroCodec(writer:, reader:) reads data of one schema as another, by Avro's schema resolution. The resolution is worked out once, when the codec is made. Schemas that do not resolve throw ResolutionException there.

Single-object encoding

encodeSingleObject and decodeSingleObject write and read a value with the fingerprint of its schema in front. SingleObjectHeader.parse reads the fingerprint of a message first, so that you can choose the codec before you decode.

Container files

  • AvroFileReader reads container files compressed with null or deflate: the header first, then the records lazily, one block at a time, with the file's schema or a codec you choose.
  • AvroFileWriter writes them, with your metadata in your order, the schema text and sync marker of your choice, and blocks that end by size or at flush.

Limits

AvroLimits bounds the schema size, the nesting of schemas and values, the decompressed size of container files and the count of zero-byte items. The defaults are finite, so a small input cannot expand without bound.
