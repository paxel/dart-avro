The ideas behind the calls of Getting started, one section each. The terms are defined in the Glossary.

Writer and reader schema

Avro data carries no field names and no types. To read it, you need the schema it was written with: the writer schema. If your code expects another shape, for example a newer version of the record, you also give the reader schema. The writer schema is then resolved against the reader schema, by the rules of the Avro specification: fields are matched by name, a field the reader adds takes its default, a field the reader drops is skipped, and an int can be read as a long. 

import 'package:avro/avro.dart';

void main() {
  final v1 = Schema.parse('''
  {"type": "record", "name": "User", "namespace": "com.example",
   "fields": [{"name": "name", "type": "string"}, {"name": "age", "type": "int"}]}
  ''');
  final v2 = Schema.parse('''
  {"type": "record", "name": "User", "namespace": "com.example",
   "fields": [{"name": "name", "type": "string"}, {"name": "age", "type": "long"},
              {"name": "email", "type": ["null", "string"], "default": null}]}
  ''');

  final old = AvroCodec(writer: v1).encode({'name': 'Ada', 'age': 36});

  final upgrade = AvroCodec(writer: v1, reader: v2);
  print(upgrade.decode(old));
}
{name: Ada, age: 36, email: null}

Defaults serve resolution only. When you encode, every field of the record must be in the map, even one with a default.

The codec

An AvroCodec is made for one writer schema and, optionally, one reader schema. It works out the resolution once, when it is made, and throws ResolutionException there if the two schemas do not resolve. Make one codec per pair of schemas and keep it.

  • encode(value) always writes with the writer schema and returns a Uint8List.
  • decode(bytes) reads one value of the writer schema and returns it in the shape of the reader schema, as an Object?. Bytes left over after the value are an error.
  • encodeJson(value) and decodeJson(text) do the same in Avro's JSON encoding.

In this package, "codec" means this object only. What the Avro specification calls a file's codec, such as deflate or zstandard, is called compression here.

Unions and Branch

A value of a union belongs to one of its branches. When you encode, the codec looks for the branches the value fits. If exactly one fits, it takes that one. The common optional field ["null", "string"] needs nothing more: null and a String each fit one branch.

If more than one branch fits, you name the branch with Branch(name, value). The name is the full name of a named type, such as com.example.User, or the type name of any other, such as long or map. 

import 'package:avro/avro.dart';

void main() {
  final number = AvroCodec(writer: Schema.parse('["int", "long"]'));

  try {
    number.encode(1);
  } on EncodeException catch (e) {
    print(e);
  }

  final bytes = number.encode(const Branch('long', 1));
  print(number.decode(bytes));
}
EncodeException at $: more than one branch fits; wrap the value in a Branch of one of int, long
1

decode returns the plain value, and a Branch only for a codec made with decodeBranches: true; without it, a union of two records with the same fields cannot be told apart after decoding. Generated code always decodes with it, so a union field of a generated class is a sealed class that knows its branch.

Logical types

A logical type gives an underlying type a meaning, such as a date on an int. Every logical type of Avro 1.12 decodes to a Dart value. Where Dart has no fitting type, the package brings its own class.

Logical typeDart value
uuid (on string or fixed of 16)String of 36 characters
time-millis, time-microsDuration since midnight
timestamp-millis, timestamp-microsDateTime in UTC
timestamp-nanosAvroTimestampNanos: nanoseconds since the epoch
dateAvroDate: year, month, day
local-timestamp-millis, -micros, -nanosAvroLocalTimestamp: wall-clock fields, no time zone
decimal, big-decimalAvroDecimal: an unscaled BigInt and a scale
durationAvroDuration: months, days, milliseconds
 
import 'package:avro/avro.dart';

void main() {
  final event = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "Event", "fields": [
    {"name": "at", "type": {"type": "long", "logicalType": "timestamp-millis"}},
    {"name": "day", "type": {"type": "int", "logicalType": "date"}},
    {"name": "price",
     "type": {"type": "bytes", "logicalType": "decimal", "precision": 9, "scale": 2}}
  ]}
  '''));

  final bytes = event.encode({
    'at': DateTime.utc(2026, 11, 21, 9, 30),
    'day': const AvroDate(2026, 11, 21),
    'price': AvroDecimal(BigInt.from(1999), 2), // 19.99
  });
  print(event.decode(bytes));
}
{at: 2026-11-21 09:30:00.000Z, day: 2026-11-21, price: 19.99}

A logical type the package does not know, or one that does not fit its underlying type, is read as the underlying type, as the specification says.

Container files

A container file starts with a header: the magic bytes, the metadata and a 16-byte sync marker. The metadata holds the writer schema as JSON text. Blocks of records follow, each one compressed on its own and ended by the sync marker.

  • AvroFileWriter(codec, compression:, metadata:, syncMarker:, schemaJson:) writes a file in memory. add adds a record, flush ends the current block, and close ends the last block and returns the file as a Uint8List. A block also ends by itself at 64 KiB before compression.
  • Your metadata comes first in the header, in your order, then avro.codec and avro.schema. Keys that start with avro. are reserved.
  • AvroFileReader(bytes, limits:) reads the header when it is made: header.metadata, header.schemaJson, header.compression and header.syncMarker.
  • records() returns a lazy Iterable that decompresses one block at a time and decodes it with the file's own schema. records(codec) decodes with a codec you choose, for example one that resolves the file's schema against yours. 
import 'package:avro/avro.dart';

void main() {
  final v1 = Schema.parse('''
  {"type": "record", "name": "User",
   "fields": [{"name": "name", "type": "string"}, {"name": "age", "type": "int"}]}
  ''');
  final writer = AvroFileWriter(AvroCodec(writer: v1));
  writer.add({'name': 'Ada', 'age': 36});
  final bytes = writer.close();

  final mySchema = Schema.parse('''
  {"type": "record", "name": "User",
   "fields": [{"name": "name", "type": "string"},
              {"name": "email", "type": ["null", "string"], "default": null}]}
  ''');

  final reader = AvroFileReader(bytes);
  final codec = AvroCodec(
    writer: Schema.parse(reader.header.schemaJson),
    reader: mySchema,
  );
  for (final record in reader.records(codec)) {
    print(record); // each record in the shape of mySchema
  }
}
{name: Ada, email: null}

The compressions are null, deflate, snappy, bzip2, xz and zstandard, all six that the specification names. A file compressed in any other way throws UnsupportedCompressionException when the reader is made. The whole file is held in memory while it is read; of its decompressed records, only one block at a time. AvroFileStreamReader and AvroFileStreamWriter read a file from a Stream and write one to a StreamSink instead, with one block in memory at a time; see Streamed container files.

Single-object encoding

Single-object encoding puts a 10-byte header in front of one value: the marker C3 01 and the CRC-64-AVRO fingerprint of the writer schema. A receiver can then tell which schema a message was written with. 

import 'package:avro/avro.dart';

void main() {
  final codec = AvroCodec(writer: Schema.parse('''
  {"type": "record", "name": "User", "namespace": "com.example",
   "fields": [{"name": "name", "type": "string"}, {"name": "age", "type": "int"},
              {"name": "email", "type": ["null", "string"], "default": null}]}
  '''));
  final message = codec.encodeSingleObject({'name': 'Ada', 'age': 36, 'email': null});

  // The receiver keeps one codec per schema it accepts, keyed by fingerprint.
  final codecs = {codec.writer.crc64: codec};

  final header = SingleObjectHeader.parse(message);
  final chosen = codecs[header.fingerprint];
  if (chosen == null) throw StateError('unknown schema');
  print(chosen.decodeSingleObject(message));
}
{name: Ada, age: 36, email: null}

decodeSingleObject throws DecodeException if the header is missing or names another schema than the codec's writer schema. Which fingerprints to accept is your decision; the package does not keep a registry.

Fingerprints

The canonical form of a schema is its Parsing Canonical Form: full names, no documentation, no aliases, no defaults and no other attributes. Schemas that differ only in those have the same canonical form. A fingerprint is a hash of it. 

import 'dart:typed_data';

import 'package:avro/avro.dart';

void main() {
  final schema = Schema.parse('''
  {"type": "record", "name": "User", "namespace": "com.example",
   "doc": "A user.",
   "fields": [{"name": "name", "type": "string", "default": ""},
              {"name": "age", "type": "int"}]}
  ''');
  print(schema.canonicalForm);

  final int crc = schema.crc64;            // CRC-64-AVRO, the 64-bit pattern in an int
  final Uint8List wire = crc64ToBytes(crc); // the 8 little-endian bytes Avro writes
  final Uint8List md5 = schema.md5;         // 16 bytes
  final Uint8List sha256 = schema.sha256;   // 32 bytes
  print('$crc ${wire.length} ${md5.length} ${sha256.length}');
}
{"name":"com.example.User","type":"record","fields":[{"name":"name","type":"string"},{"name":"age","type":"int"}]}
2748590386847567157 8 16 32

The CRC-64-AVRO fingerprint is an int, so it can be a map key as it is. It holds the 64-bit pattern, as Java's long does, so it is often negative. crc64FromBytes turns 8 bytes back into the int.

Limits

Avro data from an untrusted sender can be crafted to make a reader allocate or decompress far more than it holds. AvroLimits bounds that. The defaults are on, and finite:

FieldDefaultBounds
maxBlockBytes64 MiBOne block of a container file after decompression; in the stream reader also before, and the header
maxTotalBytes1 GiBAll blocks of a container file together after decompression
maxSchemaBytes1 MiBThe JSON text of one schema, in UTF-8 bytes
maxSchemaDepth64The nesting depth of a schema's JSON text
maxValueDepth1024The nesting depth of one value
maxZeroSizeItems1,048,576The items of one array whose items take zero bytes, such as an array of null

Schema.parse, AvroCodec, AvroFileReader and AvroFileStreamReader.open each take a limits: argument. A field set to null means no limit; AvroLimits.none turns them all off. Input over a limit throws LimitExceededException, whose limit names the field. 

import 'package:avro/avro.dart';

void main() {
  final writer = AvroFileWriter(AvroCodec(writer: Schema.parse('"string"')));
  writer.add('a record');
  final bytes = writer.close();

  const strict = AvroLimits(
    maxBlockBytes: 16 * 1024 * 1024,
    maxTotalBytes: 256 * 1024 * 1024,
  );
  final reader = AvroFileReader(bytes, limits: strict);
  print(reader.records().toList());
}
[a record]

Some checks are always on, whatever the limits: a declared length or count is checked against the remaining input before anything is allocated, negative lengths are rejected, and strings must be well-formed UTF-8.

Every failure caused by a schema, a value or bytes is an AvroException. The class is sealed, so a switch over it covers each cause. A wrong argument, such as a reserved metadata key, is an ArgumentError; Errors has the details. 

import 'package:avro/avro.dart';

void main() {
  try {
    Schema.parse('{"type": "nope"}'); // parse, encode, decode or read
  } on AvroException catch (e) {
    final reason = switch (e) {
      SchemaParseException() => 'not a valid schema',
      ResolutionException() => 'the schemas do not resolve',
      DecodeException() => 'not a valid encoding',
      EncodeException() => 'the value does not fit the schema',
      LimitExceededException(:final limit) => 'over the limit $limit',
      UnsupportedCompressionException(:final compression) => 'cannot read $compression',
    };
    print(reason);
  }
}
not a valid schema
