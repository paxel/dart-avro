# 10. Sealed unions, decoding into Branch, and a public generator for a builder

Date: 2026-11-21

## Status

Accepted. Changes the union mapping of ADR 7 and the decode result of ADR 2 (as an option).

## Context

The generated code of 0.2 maps a union with two or more non-null branches to `Object?`, and `decode` returns the plain value of a union, so a caller cannot tell which of two records arrived. Dart projects usually generate code with `build_runner`, which needs the packages `build` and `build_config`; ADR 7 keeps those out of `avro`. The gates standard knows one package per repository.

## Decision

- **Branch decoding.** `AvroCodec` takes the option `decodeBranches: true`. With it, `decode` and `decodeJson` return a `Branch` for every union with two or more non-null branches; `["null", X]` stays plain. The option is off by default.
- **Sealed unions.** In generated code, a union with two or more non-null branches becomes a `sealed class` per place of use:
  - It is named after the record and the field (`EventPayload`), with `Item` and `Value` added for array items and map values.
  - Each branch is a `final class` (`EventPayloadClick`, `EventPayloadString`) holding the branch's value.
  - A union with `null` makes the field nullable.
  - `toAvro` writes the right `Branch`; `TypedCodec` decodes with `decodeBranches`, so the branch is known even when two records fit.
  - This breaks code generated by 0.2.0 that holds `Object?`.
- **Public generator.** The generator becomes a public library, `package:avro/generate.dart`, which takes schema texts and options and returns the Dart source. The command `dart run avro:generate` is a thin wrapper around it.
- **Builder.** A `build_runner` builder, `avro_builder`, lives in a new repository, `paxel/dart-avro-builder`, with its own gates, tags and releases, and depends on that library.

## Considered options

- Sealed unions behind a flag: nothing breaks, but the documentation splits in two.
- One sealed class per distinct union, named after its branches: shared, but long and less predictable names.
- The builder as a second package in this repository: two packages, two tag patterns and two release workflows, which the gates do not support.

## Consequences

- Projects regenerate their code for 0.3.0, and a `switch` over a union field is exhaustive.
- The builder is a milestone of its own, in its own repository.
